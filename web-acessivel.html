Web acessível

Boa parte da vida cotidiana acontece online: bancos, escola, saúde, compras, serviços públicos. Se um site não é acessível, ele deixa pessoas de fora. As Diretrizes de Acessibilidade para Conteúdo Web (WCAG), publicadas pelo W3C, são a principal referência para evitar isso.

Os quatro princípios (POUR)

Perceptível
A informação pode ser percebida por diferentes sentidos. Exemplos: texto alternativo em imagens, legendas em vídeos e contraste suficiente.
Operável
Tudo pode ser usado por teclado, sem armadilhas de foco, com tempo suficiente e sem conteúdo que pisque de forma perigosa.
Compreensível
Textos legíveis, navegação previsível, idioma da página declarado e ajuda para corrigir erros em formulários.
Robusto
O código é bem formado e usa elementos semânticos, para funcionar com navegadores e tecnologias assistivas atuais e futuras.

Boas práticas para quem programa

  1. Declare o idioma: <html lang="pt-BR">.
  2. Use elementos semânticos: header, nav, main, footer, títulos h1 a h6 em ordem.
  3. Escreva texto alternativo útil nas imagens (alt) e deixe alt="" nas decorativas.
  4. Garanta contraste mínimo de 4,5:1 entre texto e fundo.
  5. Permita usar tudo com o teclado e mantenha o foco visível.
  6. Associe cada campo de formulário a um label.
  7. Use links com textos que façam sentido sozinhos (evite "clique aqui").
  8. Não dependa só da cor para transmitir informação.
  9. Respeite prefers-reduced-motion e permita ampliar o texto até 200% sem perder conteúdo.
  10. Teste com leitor de tela, só com o teclado e com ferramentas como o Lighthouse e o WAVE.

Exemplo de código

Um botão acessível usa o elemento correto, em vez de uma div clicável:

<button type="button" aria-pressed="false">
  Alto contraste
</button>

Este site aplica essas práticas. Pressione Tab para navegar apenas pelo teclado e use os botões no topo para testar o alto contraste e o aumento da fonte.
